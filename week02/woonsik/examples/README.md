# 안정 해시 코드 실험 — 13분

JDK 17 이상. Java 21에서도 실행 가능. 외부 라이브러리와 빌드 도구 불필요. 저장소 루트에서 실행.

```sh
java week02/woonsik/examples/ConsistentHashDemo.java
```

## 0~3분 — 실행 전 예상

- A:10, B:40, C:80. 키 좌표 20, 40, 90의 담당 서버 예상.
- D:30 추가 시 변경 구간, B 제거 시 변경 구간 예상. 두 변경은 각각 최초 링 기준.
- 서버 3→4 증가 시 `% N`과 안정 해시의 이동 비율 비교.

## 3~7분 — 코드 확인과 실행

1. `ownerAt`: `ceilingEntry`로 같은 좌표 포함, 링 끝에서 `firstEntry`로 순환.
2. `Ring.build`에서 물리 서버당 V개 토큰 생성. 서버 ID와 가상 노드 번호만 해싱하므로 다른 서버 추가 시 기존 토큰 유지.
3. `boundaryChecks`에서 작은 링의 구간 경계와 순환 검증.
4. `experiment`: 동일한 10만 키, 서버 A/B/C, D 추가 및 B 제거 실험.

해시: UTF-8 → SHA-256 → 상위 64비트의 부호 비트 제거, 63비트 비음수 좌표. 원형 공간 크기는 학습용 도식 100과 별개. 토큰 충돌 감지 시 덮어쓰기 대신 즉시 실패. 운영 환경에서는 결정적 충돌 처리 정책 필요.

## 7~13분 — 결과 해석과 토큰 수 변경

- `counts`: 증설 전 서버별 키 수. `CV`: 표준편차/평균, 작을수록 이 키 집합의 분배 균등.
- `add`: 증설 전후 물리 서버가 바뀐 키 비율. `remove`: 제거 대상 B가 보유하던 키 비율.
- V=1과 V=128 비교. 기대값 25%는 매번 일치하는 상수가 아님.
- `experiment(128, ...)`의 128을 16, 64, 256으로 바꿔 편차와 이동 비율 관찰. V 증가마다 CV 감소를 단정하지 않기.
- 키 수가 균등해도 `template:42` 한 키에 요청 90% 집중 시 해당 담당 서버의 요청 집중은 그대로.

검증 성공 시 `PASS` 13줄과 `All 13 checks passed.` 출력. 구간 경계, 서버 추가와 제거 시 이동 범위, 멤버 순서와 무관한 배치 확인. 이동률과 CV는 비교용으로 출력.

같은 코드로 키 10만 개를 비교한 결과. 서버별 키 수는 증설 전 A/B/C 순서.

| 방식 | 키 수 A / B / C | CV | D 추가 시 이동률 |
|---|---|---|---|
| `% N` | — | — | 74.95% |
| V=1 | 16,717 / 33,543 / 49,740 | 0.4045 | 35.47% |
| V=128 | 33,208 / 34,710 / 32,082 | 0.0323 | 22.79% |

이 배치에서 V=128의 편차 감소 확인. 서버 ID, 토큰 수, 키 집합이 달라지면 결과도 달라질 수 있음. `All 13 checks passed.` 확인.

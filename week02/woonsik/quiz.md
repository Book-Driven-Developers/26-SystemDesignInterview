# 5장 검증 퀴즈 — 10분

Discussion 게시용 문제와 해설. 대화 학습에서는 한 문제씩 진행. 1~5번 각 90초, 6번 150초.

## 문제

1. **재배치** — 해시값 0~11, 서버 `[A,B,C]`. D를 뒤에 추가해 `% 3`을 `% 4`로 변경. 이동하는 키 수와 캐시 시스템의 영향 설명.
2. **링 경계** — 0~99 링에 A:10, B:40, C:80. 키 10, 20, 40, 90의 담당 서버 계산. D:30 추가 시 변경 구간과 기존 담당자 설명.
3. **서버 제거와 기대 이동량** — 최초 링에서 B 제거 시 이동 구간과 목적지 설명. 동급 서버 3개에 키 12만 개가 균등 분배됐다고 가정. 서버 한 대를 추가할 때와 제거할 때의 기대 이동량 각각 계산. 두 변경은 독립 시행.
4. **가상 노드** — 서버당 토큰 1→128 증가의 효과와 비용 설명. “가상 노드 128개면 데이터 복제본 128개”, “V 증가마다 CV 감소”의 타당성 판단.
5. **hot key** — 키 수는 3대에 거의 균등. 한 인기 템플릿 키에 전체 읽기 요청 90% 집중. 가상 노드 증설만으로 해결 가능한지와 대안 2개 설명.
6. **운영 설계와 1분 답변** — 캐시 서버 D 추가. 일부 클라이언트는 이전 링 사용, D는 비어 있는 상태. 안정 해시 도입만으로 해결되지 않는 문제와 전환 대책 제시. 마지막 1분은 `% N` 문제→링→가상 노드→운영 한계를 자신의 말로 설명.

## 해설과 채점 기준

<details>
<summary>답변 후 펼치기</summary>

문항당 0~2점, 총 12점. 결론 오류 시 0점, 결론은 맞지만 근거 부족 시 1점, 계산과 경계 조건 및 트레이드오프까지 설명하면 2점. 총점 10점 이상, 2번, 4번, 6번 각 2점 목표.

1. 9개 이동. 0, 1, 2만 동일 서버 유지. 캐시 담당자 변경 → miss 증가 → 원본 DB 부하 상승 가능. 모든 키 이동이라는 설명은 오류.
2. 순서대로 A, B, B, A. `(10,30]`만 B→D 이동. 키 10은 A, 키 30은 D, 키 40은 B. 끝점 포함 여부와 순환까지 설명.
3. `(10,40]`의 키만 B→C 이동. 이상적 기대량: 추가 `120,000/4=30,000`, 제거 `120,000/3=40,000`. 작은 링의 실제 B 점유율은 30%로 1/3과 차이. 균등 기대값과 특정 배치의 실제값 구분.
4. 여러 구간을 나눠 받아 서버별 점유율 편차 완화, 용량 가중치 반영 가능. M=N×V가 커지면 메모리 사용량, 조회 비용, 관리 비용 증가. 가상 노드는 좌표이며 복제본 아님. 무작위 토큰 배치와 제한된 키 표본으로 인해 V 증가마다 CV 감소 보장 없음.
5. 해결 불가. 동일 키는 동일 담당자로 이동. 읽기 복제, 로컬 캐시, 요청 병합 검토. 로컬 캐시의 갱신 지연, 복제본 간 일관성 유지와 무효화 비용까지 설명하면 2점.
6. 링 버전 차이로 같은 키의 목적지 불일치, 빈 D에서 cache miss 및 원본 부하 증가. 멤버십과 링 버전 전파. 필요 시 이전 담당자 조회 또는 요청 전달. 점진적 예열, 전환 속도 제한, 원본 보호 적용. 영속 저장소라면 데이터 복사, 변경분 동기화, 전환 프로토콜 추가. 안정 해시는 위치 결정. 데이터 이전, 복제, 강한 일관성은 별도 설계.
